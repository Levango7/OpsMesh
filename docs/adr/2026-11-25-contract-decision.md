# ADR-2026-11-25 — 契约决策：v1 默认形态冻结 + opt-in 信封（方案 A）

状态：**已决策（Accepted）**　决策人：owner　日期：2026-11-25

> 背景：qa-sweep-2026-11-06 §5.4 台账中 BB-01 / BB-02 / BB-04 / BB-06 四项
> （响应形状与分页口径统一、重复入口收敛）需 owner 裁决；本 ADR 记录最终决策。

## 决策

采用 **方案 A（保守路径）**：

1. **v1 默认响应形态冻结**：客户端不携带新参数时看到的 v1 响应（字段名、类型、顶层容器、状态码、错误体）保持不变（`docs/api-versioning-policy.md` §1 D1）。
2. **opt-in 信封**：既有列表端点通过 `page` / `pageSize` 显式选择分页形态（多数为统一信封；`users`/`tenants` 为旧容器键 + 元数据历史例外）；新列表端点直接返回统一信封（`docs/api-pagination.md` §3）。
3. **新端点必须使用统一信封**：`{"data":[],"total":0,"page":1,"pageSize":20,"hasMore":false}`，空集为 `[]` 而非 `null`。
4. **破坏性变更走 v2**：BB-01 / BB-02 / BB-04 的形状统一、参数词表统一、信封统一全部留到 v2（`/api/v2/...` 或媒体类型协商），不在 v1 内做破坏性收敛。

## 理由

- 对现有前端、脚本、外部集成方 **零破坏**：默认形态逐字节兼容，不要求迁移。
- 外部集成方可通过 `page`/`pageSize` 显式 opt-in 获得分页信封与 `total`。
- 遵循 `docs/api-versioning-policy.md`（v1 默认形态冻结、不强制迁移、v2 才做统一）。
- 避免强制迁移成本与客户端回归风险。

## 被拒方案

- **方案 B（破坏性统一）**：会破坏 6 个前端视图 + 外部脚本的解析分支，回归面不可控，拒绝。
- **方案 C（渐进迁移）**：两套并行逻辑长期共存，维护成本高，且无法给出明确收敛终点，拒绝。

## 后果

- 默认形态按端点记录于 `docs/api-pagination.md` §4（端点形态表）。
- `internal/controlplane/contract_v1_test.go` 钉住 v1 默认形态（顶层键集合）与 opt-in 形态。
- 新增列表端点必须始终返回统一信封（`docs/api-versioning-policy.md` §2.2）；不得模仿 `users`/`tenants` 历史例外。
- BB-01 / BB-02 / BB-04 / BB-06 在 `docs/qa-sweep-2026-11-06.md` §5.4 台账中标记为 **已裁决（方案 A）**。
