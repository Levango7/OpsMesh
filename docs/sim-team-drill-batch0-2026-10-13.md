## 3. 发现——**经协调者独立复核**的（可信度高）

### 3.1 ✗ 误报一条（复核拦下）："HTTP 面无法授予角色"

新同事报告 D2 称 PUT `roleIDs/roleIds/roles` 全部 200 无变化 ⇒ 判"用户生命周期 API 不闭环"。
**复核**：协调者用规范名 `role_ids` 做同一操作——PUT 200 且**库内角色真的变了**
（`coord-probe-1` role-viewer→role-operator）。⇒ "无法授予角色"不成立（人设用了错误字段名）。
**但**它暴露的真问题是下面的 3.3（未知字段静默 200 —— 让人按错误字段名探测时得出反的结论）。

### 3.2 【真·中】建号 `POST /users` 忽略 `mustChangePassword`

- 人设证据：带 `mustChangePassword:true` 建号被忽略；**协调者复核**：同样请求 → 库内
  `mustChangePassword=False`（响应也回 false）⇒ 确认。**含义**：管理员经单体 HTTP 面**造不出
  "首登强制改密"账号**（auth-svc 侧支持——`cutover-migrate --force-change` 走的就是对侧）。
  两侧不对称，而首登改密恰是切流交接口令的关键机制。**建议**：单体建号透传该字段（与对侧对齐）。

### 3.3 【真·中低】PUT 对未识别字段静默 200（F6 同族）

- 复核：PUT `{"roles":["role-admin"]}` → **200 但库内角色没动**。同一接口换规范名 `role_ids`
  立即生效。⇒ 客户端拼错字段名时拿到"成功"假象。**建议**：未识别键拒绝（400）或在响应里
  回显"实际生效的字段"，别让 200 覆盖 no-op。

### 3.4 【真·低】建号响应形状失真

- 复核：响应 `createdAt:"0001-01-01T00:00:00Z"`（库内 2026-10-13T16:40:49Z）、`permissions:null`。
  即响应回显的是请求对象而非落库对象。**建议**：建号后回读落库对象。

### 3.5 【真·中低】审计 `userID` 字段语义分裂 + 身份不符行的 actor 可伪造

- 复核（原始 JSON 逐字段）：`action=authz_denied` 行 `userID="drill-u04"`（**用户名**）；
  `action=user_login` 行 `userID="user-admin"`（**存储 ID**）。同一字段两种含义 ⇒ 按 actor
  单一键对账必漏（审计人设的"双口径"发现成立）。另：身份不符 403 的留痕取**客户端自称的
  X-User-Id 头值**（人设实测两条伪造署名入库）⇒ 按 actor 追责会被带偏，真实 JWT 主体缺失。
  **建议**：统一为存储 ID（用户名另置字段）；身份不适用时记"未知"而不是采信自称头。

### 3.6 【真·中高】存储故障伪装成凭证错误 → 故障放大成锁号（**两个人设独立复现**）

- 证据：宕机窗口内任意账号登录 → `401 invalid username or password`（运维/新同事各复现多轮）；
  且失败**计入防爆破**（运维 5 次 → 429 锁定 15 分钟；审计 5 次 → 同样）。恢复后原口令立即可登。
  ⇒ 一次后端抖动 = 全体用户被"看起来像密码错"击退 + 活跃用户被锁 15 分钟。**建议**：
  store 错误与凭据错误分流（5xx/维护态，不计数）——与本仓"不把'未知'伪装成'缺陷'"同一条纪律。

### 3.7 【真·中】故障期 refresh 被误路由到对侧、会话被销毁

- 证据（运维）超时窗口内 rt 刷新 → 401 `refresh failed` + 清 Cookie；健康态同流程 200 ✓。
  因果链为代码+时间线推断（人设标注"未做故障注入复现"）。⇒ 与 3.6 同源（store 读失败的
  处理把"查不到"当成"不归我管"）。**建议**：与 3.6 一并立项（切流前必修——回退语义依赖 rt 归属判定）。

### 3.8 【真·中低】两个审计端点的租户语义不一致

- 复核（人设原始 JSON）：`GET /api/v1/audits`（不带 tenant 参数）返回**全租户** 96 条，且
  `?tenant=<他租户>` 可定向读；而同库 `GET /api/v1/audit/events` 严格收敛 default。
  本演练部署 `requireAuth=false`（默认），代码注释称此时隔离交给前置网关——但控制面自身
  仍执行 RBAC，"网关兜底"前提在本形态下不成立。**建议**：两个端点统一租户口径。

### 3.9 【真·低】agent 列表无 lastHeartbeat、死进程恒 online

- 复核：`GET /api/v1/agents` 行仅有 `{agentID,hostname,segment,status:"online"}`——**连
  心跳时间字段都没有**；而人设实测其 agent 进程已停 ≥7 分钟仍 online。⇒ 运维无法看出"这台
  agent 已经失联多久"。**建议**：列表补 lastHeartbeat（或至少补 status 的过期判定）。

### 3.10 【真·低】会话过期/未认证的文案三套并存、无"请重新登录"

- 证据（两个人设）：过期后 `/devices`→400 `missing X-Tenant-ID header`、`/admin/*`→401
  `missing identity`、`/auth/me`→401 `missing Authorization header`；首屏根路径 `/`→**中文纯文本**
  400 租户头错误，其余全英文 JSON。⇒ 与历史演练 F1 同族（切换/过期对用户零引导）。

### 3.11 【真·低】零角色账号可登录且零提示

- 新同事：建出的无角色账号登录 200、permissions 空、无任何提示，此后每个读取 403。
  ⇒ 真实新人会判定"系统坏了"。**建议**：登录响应/首页对零权限给出显式指引。

### 3.12 【策略待裁定】operator 建得了任务、取消不了

- 运维实测：`POST /tasks` 201 ✓，但取消自己建的任务 403 `task:cancel`（×3；admin 同接口 200）；
  同理 `alert:ack/silence` 均不在 operator 权限集。⇒ 值班角色"能开不能关"是否符合设计意图，
  属**产品决策**（记入待裁定，不按缺陷处理）。

3. **A1**：裸注册 agent 落默认租户且立即可见（运维 ×2 复核；`sim-users.sh` 试跑另有旁证）。
4. **A2**：带 `X-Tenant-ID` 身份回填正确（两人设各验一次）。
5. **B3**：404 统一 JSON 信封且带 path；**B4**：登录/刷新响应带 permissions（两人设核对条数）。
