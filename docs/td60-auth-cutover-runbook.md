# TD-60 auth 收敛运维 Runbook（分批切换执行手册）

> **适用范围**：按决策单 Q1-A（文件名册）+ Q2-A（job 搬号）+ Q3-A（允许切换即重登）执行
> 「控制面本地 auth → auth-svc」的分批收敛。前置条件与机制说明见
> `docs/td60-cutover-signal-design.md` §10.4 与 `docs/td60-domain-convergence-analysis-2026-10-11.md` §3。
> 全线可回退；**任何一步异常先回退再排查**，不带着半切状态过夜。

---

## 0. 前置检查（每次执行前 5 分钟）

```bash
# ① 双轨机制就绪：代理面通、名册文件在位
curl -s -o /dev/null -w '%{http_code}' http://<控制面>/api/v1/auth-svc/me   # 期望 401（端点在、需凭证）
# ② auth-svc 侧健康：管理端点可达
curl -s -o /dev/null -w '%{http_code}' http://<auth-svc>/api/v1/users        # 期望 401/403（需管理员凭证）
# ③ 名册文件路径与当前内容（控制面 30s 轮询热加载）
cat "$AUTH_CUTOVER_ROSTER_FILE"
```

**准入判据**：三条都符合才进第 1 步；任何一条不符 → 停，先修再排期。

## 1. 批次划分（提案 §11 参数）

| 批 | 范围 | 观察窗 | 备注 |
|---|---|---|---|
| **第 0 批（彩排）** | 1 个**内部/演示**租户的用户 | 2 个工作日 | 不惊动真实客户；目标=验证全流程而非切流量 |
| **第 1 批** | 1 个**低风险真实**租户（愿意配合、有直接联系人） | 2 个工作日 | 第一次真实流量验证 |
| **第 2 批起** | 每批 **≤5% 租户且 ≤3 个租户**（取小者） | 2 个工作日 | 稳定后翻倍 |
| 上限 | **25% 封顶** | — | 超过必须重新评估 |
| 最后一批 | **不要把最大/最复杂的客户留到最后一把** | — | 单独成批、单独通知 |

**保留账号永不入册**：`admin`（两侧 seed 同名，job 装载期即拒）。

## 2. 单批执行（五步）

### 2.1 预热（切换前 ≥3 个工作日，非本机操作）

在 auth-svc 侧为**本批全部用户**建号并审批。**门槛**：该批全部用户都能在 auth-svc 侧完成一次登录
（影子路径自测，不经控制面）——未达成不进下一步。

> **2026-10-12 更新（已透传）**：`opsmesh cutover-migrate --force-change` 建号时即置
> `mustChangePassword`（对侧入口 `3261169` + 本侧透传 `8870d69`）⇒ 一次性口令真正**只用一次**，
> 用户首次登录即被要求改密。**执行第 2.3 步时请带上 `--force-change`**——不带则该口令就是
> 长期口令（旧行为，仅当批次用户明确接受长期口令时才这样跑）。口令交接口径见 §4。

### 2.2 用户通知（切换前 1 个工作日）

告知本批用户：**切换后需重新登录一次**（Q3-A 语义：旧会话不被对侧承认）。
不专门做前端提示（Q4 建议 A/B 由产品定）。

### 2.3 切换（写名册）

```bash
# dry-run 先看计划（零副作用：不建号、不写名册）
opsmesh cutover-migrate --users alice,bob --dry-run \
  --auth-svc-url http://127.0.0.1:8100 --auth-svc-admin-password '***' \
  --store mysql --mysql-dsn '...'

# 确认无误后执行（幂等：已在对侧 active 的用户只收编、不建号）
# —— 建议带 --force-change：一次性口令只使用一次，用户首登即须改密（见 §2.1 注）
opsmesh cutover-migrate --users alice,bob \
  --auth-svc-url http://127.0.0.1:8100 --auth-svc-admin-password '***' \
  --store mysql --mysql-dsn '...' --force-change \
  --credentials-out /secure/creds-batchNN.txt
```

判据：退出码 0（全成功）；有失败 ⇒ 只重跑失败者（幂等）。

### 2.4 生效与抽验（切换后 30s 内）

控制面 30s 轮询热加载名册。抽验三条：

| 抽验 | 期望 |
|---|---|
| 本批用户经控制面 `/api/v1/auth/login` 登录 | **200**（由 auth-svc 应答） |
| 本批用户**旧本地口令**登录 | **401**（路由已切走） |
| 非本批用户登录 | **200 且走本地**（控制面路由日志无该用户的转发记录） |

### 2.5 观察窗（2 个工作日或覆盖一次登录高峰，取长）

每小时看一次；触发任一回退判据立即按 §3 回退。

## 3. 回退

**单用户回退**（首选，粒度=名册条目）：

```bash
# 从名册文件摘除该用户（控制面 30s 热加载，无需重启）
sed -i '/^alice$/d' "$AUTH_CUTOVER_ROSTER_FILE"
```

**整批回退**：摘除本批全部条目。回退后旧本地口令重新生效（路由回本地）。

**硬回退**（面级）：把 compose 的 `AUTH_CUTOVER_ROSTER_FILE` 置空并重启控制面 ⇒
名册为空、全部回本地登录面。

**回退必做**：通知本批用户“需重新登录一次”；回退后 24h 内不重切该批——
重切前必须查清原因并把漏检点补进 §2.1 门槛。

## 4. 凭据交接（一次性口令）

`cutover-migrate` 输出的一口令是**一次性随机强口令**（24 位四类字符）：

- 默认打到 stderr（运维终端）——**注意终端历史与会话录屏**；
- 生产必须用 `--credentials-out <path>`（落盘 0600，建议放保密目录）。
- 交接后**立即删除该文件**；口令只经安全渠道给用户本人（禁止进工单/IM）。
- **带 `--force-change` 时**：清单头部会写「口令只使用一次，首登即要求改密」——
  交接时顺带告知用户"首次登录会跳改密页"，免得上线后误以为故障；交接口径与不带时相同。

**一个已复核的边界（peer 独立验收时提出）**：口令/路由 ID 不进指标标签
（`route` 标签来自服务端生成的十六进制 ID、`tenant` 来自已校验的令牌声明），
且渲染侧对标签值有白名单收紧（非白名单字符折叠为 `:other`，无法伪造额外标签）。
这两点由 `TestGatewayMetricLabelsNotUserControllable` 常驻守着。

## 5. 回退判据（观察窗内任一命中即停批回退）

| 判据 | 阈值 |
|---|---|
| 本批登录失败率 | > 切换前同租户基线 **+0.5 个百分点** |
| “用户不存在”/凭证无法解析类错误 | 出现**任意一次**（非密码错） |
| 本批 401/403 请求数 | > 基线 **2 倍**且绝对值 **≥10** |
| auth-svc 不可用 | 任意时长（控制面代理层会 502/503） |
